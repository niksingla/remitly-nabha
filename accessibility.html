Accessibility

A payments site that only works for some people is a broken payments site. Here is what this build does, and an honest list of what it does not.

Our aim

This project targets the WCAG 2.2 Level AA success criteria. It is a practice build rather than an audited product, so treat the list below as a statement of intent backed by implementation, not a certified conformance claim.

What has been implemented

  • Semantic structure — one <h1> per page, headings in order without skipped levels, and landmark elements for the header, navigation, main content and footer.
  • Keyboard access — every interactive control is reachable and operable by keyboard. Navigation menus close on Escape, tab lists respond to arrow keys, and focus is never trapped.
  • Visible focus — a high-contrast focus ring is applied through :focus-visible and is never removed.
  • Skip link — the first tab stop on each page jumps straight to the main content.
  • ARIA where it is needed — accordions, tab panels and dropdown menus expose correct aria-expanded, aria-controls and aria-selected state, and no further.
  • Labelled form fields — every input has an associated label, with visually hidden labels used where the design calls for no visible text.
  • Colour contrast — body text and interactive controls meet the 4.5:1 ratio against their backgrounds; large headings meet 3:1.
  • Colour is never the only signal — status is always carried by text as well as colour.
  • Decorative images hidden — the illustrative phone, card and thumbnail graphics are marked aria-hidden so they are not announced.
  • Reduced motion respected — all transitions and scroll reveals are disabled under prefers-reduced-motion.
  • Zoom and reflow — layouts reflow to 320 pixels wide and survive 200% text zoom without clipping or horizontal scrolling.
  • Relative units — type is sized in rem so it scales with the browser's base font size.

Known gaps

Being specific about failures is more useful than a blanket claim of compliance:

  • The site has not been tested end to end with screen readers. Components follow established ARIA patterns, but that is not a substitute for testing with VoiceOver, NVDA and JAWS.
  • There is no automated accessibility test suite in the project, so regressions would not be caught.
  • Wide data tables scroll horizontally on small screens. This is announced to assistive technology but is still awkward to navigate.
  • Form validation messaging is not implemented, because the forms are deliberately inert. A real build would need inline errors tied to fields with aria-describedby and an error summary.
  • The site is English only. A genuine service operating in eighteen languages would need full localisation including right-to-left layout support.
  • Contrast has been checked by eye and by ratio calculation rather than with a tooling pass across every state and component combination.

Testing this yourself

If you want to check the claims above, these are quick to try:

  1. Press Tab from the top of any page. The skip link should appear first, and every control should show a focus ring as you move through.
  2. Open a navigation menu with Enter, then press Escape. It should close and return focus sensibly.
  3. Set your browser zoom to 200%. Nothing should be clipped or require sideways scrolling.
  4. Narrow the window to around 320 pixels. The layout should stack rather than overflow.
  5. Turn on "reduce motion" in your operating system and reload. Animations should not play.

Feedback

On a real site this section would give a monitored address for accessibility problems, commit to a response time, and offer an alternative route to complete any task that could not be made accessible. As this is a static demonstration, the contact page addresses are placeholders and nothing sent to them is received.

Why this page exists at all Accessibility statements are a legal requirement for many organisations and a good idea for the rest. Including one here demonstrates the full shape of a production website — and writing down the gaps is a more useful exercise than claiming there are none.
